# Отказоустойчивость
## Kafka
Минимум 3 ноды для каждого топика по реплике на каждую ноду
Для логов без подтверждения записи
Для показов с подтверждения минимум от 1-й реплики
RPO - для логов допустимы потери не прочитанных логов  1 сутки
для показов не допустимо.
RTO - не более 15 минут
## PostgreSQL
### Для сервиса компаний и сервиса финансов
Для каждого инстанса минимум 1 реплика с включенным failover
Бекап 1 раз в сутки с хранением логов за 1 день
RPO - недопустима потеря закоммиченных данных
RTO - менее 1 минуты при failover
### Для сервиса аукционов 
Бекап 1 раз в сутки с хранением логов за 1 день
RPO - Допукается потеря части данных
RTO - 5 минут на создание новой базы
до 1 дня востановления данных из бекапа

# 12 факторное приоложение
- 6. Процессы (Processes)
все сервисы stateless данные храняться в БД
- 7. Порт привязки (Port Binding)
Реализуется через API Gateway
- 8. Конкурентные процессы (Concurrency)
Разделение процессов через шардирование по ключам аукциона/компании
- 9. Утилизируемость (Disposability)
За счетк stateless и Concurrency процессы могут быть быстро перезапущенны
- 11. Логи (Logs)
 собираем logstash(аналогом ) пишем в Kafka
